# 이 블로그에 대해

백엔드 개발자로 일하면서 공부한 것과 직접 겪은 문제를 정리하는 곳이다. 정의를 외우기보다 "실무에서 어떻게 판단하는가"를 남기는 데 목적이 있다.

## 글의 종류

| 종류 | 담는 것 | 시작점 |
|---|---|---|
| 개념 노트 | Java, Spring, DB, Redis 같은 기본기와 트랜잭션, 동시성, 성능 같은 실무 주제 | [[00-home/index\|홈]]의 주제 지도 |
| 내 실무 사례 | 직접 겪은 문제를 회사·시스템 이름 없이 일반화한 글 | [[work-cases\|내 실무 사례]] |
| 설계 사례 | 자주 부딪히는 설계 문제를 공식 문서 근거와 함께 풀어 본 글 | [[design-cases\|설계 사례]] |

## 쓰는 기준

- **문제부터 쓴다.** 이 개념을 모르면 어떤 버그나 장애가 생기는지를 먼저 쓰고, 원리와 해결은 그다음에 쓴다.
- **대가를 같이 쓴다.** 장점만 쓰지 않고, 무엇을 잃는지와 어디서 깨지는지를 같이 쓴다.
- **확인한 것만 쓴다.** 숫자와 동작은 공식 문서, 코드, 실행 결과로 확인한 것만 쓴다. 버전에 따라 달라지는 내용은 기준 버전을 적는다.
- **회사 정보는 쓰지 않는다.** 실무 사례는 회사, 시스템, 테이블, URL을 지우고 `order`, `payment` 같은 일반 이름으로 바꿔 쓴다.
- **AI는 초안과 검토에만 쓴다.** AI가 만든 문장은 그대로 올리지 않고, 사실은 따로 확인한다.

글마다 끝에 "한 번에 설명하기"가 있다. 그 주제를 1분 안에 말로 설명한 요약이다.

# 배치 모니터링

배치 모니터링은 실행 성공 여부만이 아니라 처리 건수, 실패 건수, 지연, 재시도, 누락까지 보는 일이다. 프로세스는 성공했는데 실제로 처리한 건수가 0건인 경우가 있기 때문이다. 프로세스 성공과 업무 성공은 다르다.

## 무엇을 보나

| 지표 | 의미 |
|---|---|
| success/failure count | 실행 결과 |
| processed count | 실제 처리량 |
| failed item count | 부분 실패 |
| duration | 지연과 병목 |
| retry count | 불안정한 의존성 |
| last success time | 누락 감지 |

처리 건수, 실패 건수, 실행 시간, 마지막 성공 시각이 기본이다. 실행 시간이 조금씩 길어지는 것은 장애 전조일 때가 있으니 추세로 본다.

## 자주 깨지는 곳

- **프로세스 exit code만 보고 성공으로 판단한다.** 0건 처리나 부분 실패를 놓친다.
- **처리 건수와 대상 건수를 비교하지 않는다.** 누락이 늦게 발견된다.
- **실패 알림이 없거나, 기준이 너무 낮아 노이즈가 많다.** 알림은 받은 사람이 할 일이 있는 기준으로 건다.
- **batch id 없이 로그를 남긴다.** 실패 로그가 있어도 어느 실행, 어느 대상인지 추적할 수 없다.

## 운영에서 볼 것

- batch id로 로그, 메트릭, 처리 결과를 이어 볼 수 있는지 확인한다.
- 마지막 성공 시각이 기대 주기를 넘으면 알림이 가는지 확인한다.
- 실패 건수와 재시도 횟수가 dashboard에 보이는지 확인한다.

## 한 번에 설명하기

> 배치는 프로세스가 성공했는지보다 실제로 무엇을 처리했는지를 봐야 합니다. 저는 처리 건수, 실패 건수, 실행 시간, 마지막 성공 시각을 기본 지표로 두고, batch id로 로그와 결과를 연결합니다. 알림은 받는 사람이 바로 행동할 수 있는 기준으로 걸고, 마지막 성공 시각으로 누락을 잡습니다.

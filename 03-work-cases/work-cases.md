## 글의 구성

사례 글은 모두 같은 순서로 쓴다. 처음 읽을 때는 맨 위 요약 표와 "한 번에 설명하기"만 봐도 된다.

| 순서 | 내용 |
|---|---|
| 요약 표 | 무엇을 했고, 왜 어려웠고, 어떻게 풀었고, 무엇이 남았나 |
| 흐름 | 구조나 처리 순서를 그린 그림 |
| 원인과 해결 | 원인을 어떻게 좁혔고, 무엇을 골랐고, 무엇을 고르지 않았나 |
| 정상 vs 장애 | 상황마다 무슨 일이 일어나고 어떻게 대응하나 |
| 다시 만든다면 | 지금 알았다면 처음부터 다르게 할 것 |
| 한 번에 설명하기 | 60초 요약과 꼬리 질문 |

## 쓰는 기준

- 회사, 시스템, 테이블, URL, 로그 원문은 쓰지 않는다.
- 숫자는 공개해도 되는 범위에서, 원문으로 확인한 것만 쓴다.
- "개선했다"로 끝내지 않고, 원인을 어떻게 좁혔는지가 보이게 쓴다.
- 고르지 않은 대안과 그 이유, 남은 약점도 같이 쓴다.

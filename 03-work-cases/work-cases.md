## 문서 구성

모든 사례는 같은 순서로 쓴다. 처음 읽을 때는 맨 위 요약 표와 "면접에서 말하기"만 봐도 된다.

| 순서 | 내용 |
|---|---|
| 요약 표 | 무엇을, 왜 어려웠고, 어떻게 풀었고, 무엇이 남았나 |
| 흐름 | 구조나 처리 순서 그림 |
| 원인과 해결 | 어떻게 좁혔고, 무엇을 골랐고, 무엇을 고르지 않았나 |
| 정상 vs 장애 | 상황별로 일어나는 일과 대응 |
| 다시 한다면 | 지금 알았다면 처음부터 다르게 할 것 |
| 면접에서 말하기 | 60초 답변과 꼬리 질문 |

## 작성 원칙

- 회사, 시스템, 테이블, URL, 로그 원문은 쓰지 않는다.
- 숫자는 공개해도 되는 범위에서, 원문으로 확인한 것만 쓴다.
- "개선했다"보다 "원인을 어떻게 좁혔는가"가 보여야 한다.
- 고르지 않은 대안과 그 이유, 남은 약점도 같이 쓴다.
